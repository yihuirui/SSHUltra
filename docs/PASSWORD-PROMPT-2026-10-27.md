# 0.2.2 留空密码的终端认证

日期：2026-10-27。用户要求：连接配置未填写密码时，在对应终端区域提示输入，避免直接发送空密码后认证失败。

主 Agent 直接负责 SSH 认证回调、现有认证 IPC、终端内隐藏输入与回归；边界为同一认证链路，没有委派。未读取或修改真实业务主机、Keychain 或用户工作区配置。无实际移动、无删除用户项目资产；只清理测试自身临时夹具。0.2.0、0.2.1 成品保留，新的预览版本为 0.2.2，尚未推送 GitHub。

## 原因和行为

原先连接表单把空字符串作为密码提交；ssh2 尝试完配置的方法后，服务器拒绝认证，返回 All configured authentication methods failed。SSH 远端 shell 尚未建立，因而原先没有能接收后续密码输入的通道。

现在，密码为空或未提供时使用 ssh2 的异步 authHandler。先完成主机指纹核对，再由服务器返回允许的认证方法。支持 password 时，复用按窗口／会话随机 token 管理的认证 IPC，在对应终端区域显示 Password 隐藏输入框；提交后直接用于 SSH 认证，不经过 xterm 的输入或回滚缓冲区。已经填写的密码和安全凭据保持原流程；服务器只支持 keyboard-interactive 时继续使用已有 MFA 交互窗口。无自动重试远端命令。

- 输入框显示当前认证端点的用户名、主机和端口；跳板和目标机独立提示，分别验证指纹。
- 按 Enter／“继续连接”提交；Esc／“取消连接”取消；60 秒未回答自动过期。
- 只阻止该等待认证终端的普通输入，其他已连接会话仍可使用；切回等待认证的标签时聚焦密码框。
- 提交、取消或卸载时清空输入；不把密码写入配置、凭据库、日志或滚屏。认证完成后移除输入框。
- 取消、超时、关闭和迟到回答不会建立遗留 shell；手动重连保留原终端内容并再次询问密码。

## 修改位置

`desktop/ssh.cjs` 新增延迟密码认证回调；`desktop/main.cjs` 复用现有认证事件并附加终端展示位置和端点身份；`src/App.tsx` 将终端请求与 MFA 模态请求分流；`src/TerminalPane.tsx` 增加独立隐藏输入表单和焦点／普通输入保护；`src/types.ts` 与 `src/workflows.css` 补充接口、样式。README、架构、发行说明、变更记录和 CI 同步更新。
